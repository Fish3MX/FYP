# LLM-Driven UAV Test Scenario Generation

[English](README.md) | [中文](README.zh-CN.md)

Turn a natural-language test request into a flyable, verifiable UAV scenario inside Unreal Engine / AirSim.

---

## What this is

| Layer | Does what | Where |
|---|---|---|
| LLM | writes a scenario specification (JSON) from a request | `src/llm_compiler.py` |
| Program | validates and geometrically verifies that specification | `src/verifier.py` |
| Engine | instantiates the objects and renders the views | `src/scene_builder.py` |

Model does **not** generate 3D meshes. Scenes are assembled from assets the simulator already ships with.

## Dependencies

- **Simulation**: OpenUAV / TravelUAV, `closeloop_envs` only (`ModernCityMap` used so far).
- **Python**: 3.10 environment with `airsim`, `numpy`, `pillow`.
- **Hardware**: NVIDIA GPU; headless rendering works, no display required.

```bash
pip install -r requirements.txt
python -c "import airsim; print('airsim ok')"
```

## Configuration

Credentials live outside the code. Either export them, or copy the template:

```bash
cp .env.example .env
chmod 600 .env          # fill in LLM_API_KEY
python scripts/check_llm.py
```

`LLM_BASE_URL` and `LLM_MODEL` default to DeepSeek. Any OpenAI-compatible endpoint works.
`.env` is git-ignored; a real environment variable overrides the file.

## Connecting to OpenUAV

### Changes OpenUAV's own environment needs

These belong to OpenUAV's `requirements.txt` and setup, not to this repository.

| Change | Why |
|---|---|
| comment out `flash-attn==2.5.9.post1` | it builds the model OpenUAV ships; this project never loads it |
| pin `msgpack==0.6.2` | `msgpackrpc` passes `encoding=`, which msgpack 1.0 removed; 1.x breaks the import |

The pin has a side effect: with 0.6.2 a Python `str` is packed as *raw* and arrives as `bytes`, which the server compares against `str` keys.

**Patch `AirVLNSimulatorServerTool.py` (around line 591)**

Without it the server cannot match the scene id it receives and raises `KeyError: can not find scene file`.

```python
for item in scen_id_gpu_list:                      # line 591
    if isinstance(item[0], bytes):                 # added
        item[0] = item[0].decode('utf-8')          # added
```

### Start the scene

Set `OPENUAV_ROOT` to your own checkout; paths differ per machine.

```bash
export OPENUAV_ROOT=/path/to/OpenUAV     # <-- change this
cd $OPENUAV_ROOT/closeloop_envs

bash ./ModernCityMap.sh \
  -RenderOffscreen -NoSound -NoVSync -GraphicsAdapter=0 \
  -settings=$OPENUAV_ROOT/airsim_plugin/settings/30001/settings.json
```

| Flag | Meaning |
|---|---|
| `-RenderOffscreen` | render without opening a window; works headless over SSH |
| `-NoSound`, `-NoVSync` | disable audio and vertical sync |
| `-GraphicsAdapter=0` | use GPU 0 |
| `-settings=` | AirSim config; defines `ApiServerPort`, vehicle name and cameras |

The port you connect to is **`ApiServerPort` inside that settings file** (30001 here), not the launcher's port.
That file was generated by OpenUAV's server tool; it sets `LockStep: true`, so asynchronous flight commands block. This pipeline only teleports the vehicle and captures images, so it is unaffected. Flight tests need a settings file with `LockStep: false`.

### Verify the connection (optional but recommended)

```bash
python tools/onboard_scene.py --port 30001 --scene openuav_moderncity \
    --emit-spec specs/onboard_smoke.json
```

Six checks: import, connect, vehicles, assets, spawning, images. Writes `runs/onboard/profile_<scene>.json`.

## Closed loop

```bash
# 1. once per scene: verify it and write the profile
python tools/onboard_scene.py --port 30001 --scene openuav_moderncity \
    --emit-spec specs/onboard_smoke.json

# 2. build and render (no model, no geometry verification)
python scripts/main.py --spec specs/onboard_smoke.json \
    --scene-profile runs/onboard/profile_openuav_moderncity.json \
    --no-verify --out runs/render_1

# 3. check the images without looking at them
python scripts/inspect_run.py --run runs/render_1

# 4. with a model instead of the template
python scripts/main.py --request "a drone searching for a survivor in a burning two-storey apartment" \
    --scene-profile runs/onboard/profile_openuav_moderncity.json \
    --no-verify --out runs/render_2

# 5. generation statistics across many requests
python scripts/batch_compile.py --trials 3 --tag main
```

| Command | Produces |
|---|---|
| `onboard_scene.py` | `profile_*.json`, `onboard_report.json`, one screenshot |
| `main.py` | `spec.json`, `render_report.json`, `images/<shot>/<view>.png` |
| `inspect_run.py` | brightness/contrast table, flags black or flat frames |
| `batch_compile.py` | `results.csv`, `summary.json`, failure taxonomy |

`--no-verify` is required on a packaged map: the verifier models only the objects a spec declares, not the map's own buildings.

## Other notes

- `runs/` and `*.npy` are git-ignored; experiments never enter the repository.
- `tests/test_offline.py` needs no engine, no GPU and no network: `python tests/test_offline.py`.
- `specs/fire_floor2.json` is a legacy reference written for a different map (CityStreet). The test suite still uses it as a fixture.
- `src/asset_catalog.py` currently describes CityStreet assets and will be rebuilt against the OpenUAV profile.
